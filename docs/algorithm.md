# 算法设计与证明边界

## 为什么不能只搜节点图

节点连线只说明“作者声明了一条选择”，不能证明当前变量能让玩家采用它。例如门前节点第一次到达时没有钥匙，离开取钥匙后再回来才可以开门。如果只对 `node_id` 去重，第二次到达就会被漏掉。`examples/state_cycle_ok.json` 专门覆盖这种情况。

分析以 `(node_id, bitmask)` 为不可变状态。将变量 ID 按字符串排序，第 0 个名字对应最低位，依次使用第 1、2、……位；位为 1 表示 `true`。初始掩码由 `variables` 中的初始值构造，快照按相同顺序还原。变量在 JSON 中的声明顺序不会改变位序。

选择条件读取源掩码，赋值在副本上设置或清除对应位，再组成目标状态。清除位实现赋值回 `false`。这样不同分支之间没有可变状态共享，也没有隐含节点效果。

## BFS 与最短路径证据

从起始状态开始使用 FIFO 队列。首次发现状态就立即放入去重表，并保存“父状态、采用的选择”。按输入选择数组顺序展开所有条件成立的边；再次进入同一状态不重复展开，但仍保存这条实际有效转移。

每条选择算一步，因此 BFS 首次发现某状态的父链就是到它的最少选择次数路径。并列时沿用输入选择顺序，使证据可重复。恢复证据时迭代追溯父指针、反转步骤，计算相邻状态间实际改变的变量。不会从抽象节点连线拼接路径。

断言在初始状态及每个新发现的目标状态上检查。由于断言只依赖当前位置与赋值，相同状态不需要重复检查；失败不会截断后续搜索。`ending=true` 的状态检查断言后终止，不生成出边。一个非结局状态完整展开后如果没有有效边，就证明了死路。

按 `(code, node_id, choice_id, assertion_id)` 聚合问题，统计受影响的不同状态，最多保留三条代表性路径。BFS 发现顺序天然优先保留较短路径；不把同一状态的多次到达算作多个问题状态。全局诊断和不可达诊断不伪造到达证据。

## 反向状态可达分析

完整搜索后，在所有**已到达的结局状态**上初始化反向队列。沿完整记录的有效状态转移反向搜索，得到“仍存在至少一条路线能到结局”的状态集合。其补集中的可达非结局状态报告 `NO_ENDING_PATH`，已经是 `DEAD_END` 的同一状态除外。

必须在状态图上做这个步骤。同一个剧情节点可能分别以“仍持有证据”和“证据已消耗”到达，前者还能结束，后者只能困在循环中；把它们合并成一个节点会掩盖问题。

循环本身不是错误。有出口的循环、可返回拿钥匙的路线和自环都能由状态去重自然终止搜索。即使玩家可以永远绕圈，只要仍存在结束路线，就不会因此报 `NO_ENDING_PATH`。此检查不保证所有玩家策略都最终结束。

## 局部矛盾与实际不可用

局部条件检查先提取表达式中不同变量的集合。最多 12 个时，枚举它们的全部布尔赋值；只要有一个使条件成立，就不是逻辑矛盾。常量也适用：`false` 矛盾，`true` 可满足。相同不可变条件缓存检查结果。

超过 12 个变量时明确记录 `skipped` 及原因；不默认通过，不猜测矛盾，也不影响实际搜索中的条件求值。表达式最大深度 32 由输入校验限制，不支持任意 Python 表达式。

某个可满足条件仍可能在这个故事中永远无法成立，例如没有任何可执行效果能把它要求的变量设为 `true`。只有完整搜索后，源节点可达且该选择在所有可达源状态中都未触发，才报告 `NEVER_ENABLED_CHOICE`。源节点不可达时不逐项重复报；已报矛盾的选择也不再报一次。

## 上限与“不完整”

`max_states` 限制唯一发现状态数，默认 50000；`max_transitions` 限制有效状态转移数，默认 200000。二者必须是正整数。只有继续处理某条有效转移确实需要超出上限时才停止，刚好达到限制但图已经完整时不会误报未完成。

已发现不等于已完整展开。截断时队列中可能还有未展开状态，正在展开的状态也可能只处理了部分选择；这些状态不能当作没有选择的死路。计数会分别给出发现数、完整展开数、记录的转移数和停止原因，不会越过限制继续偷偷搜索。

未完成时保留已证实的可达路径、断言失败和完整展开状态的死路。不可达、始终不可用和没有结束路线等否定结论需要全量图，因此一律不在未完成搜索中输出；未发现节点和未触发选择标为未知。报告状态为 `incomplete`，CLI 退出码为 3，无论是否已经出现 error。

## 复杂度与适用范围

若有 N 个节点、V 个布尔变量，理论状态数上界是 `N × 2^V`。设实际可达状态数为 S、有效转移数为 E，BFS 和反向搜索的图处理成本为 O(S+E)，内存也与 S+E 相关；实际时间还包括各状态中选择条件求值、断言求值、局部条件枚举及报告证据生成。每个局部表达式最多枚举 `2^12` 个赋值，枚举成本还乘以表达式求值成本。

因此控制变量规模比仅控制节点数更重要。工具提供明确的状态和转移限制，而不承诺大型故事总能完整分析。报告不导出整个状态图，证据只保留有限代表路径，避免把完整图无必要地复制到输出文件。

完整无问题只证明：在给定布尔模型、初始值、所有可执行选择与作者写出的断言下，未发现这些诊断所描述的问题。它不评价文笔，不保证现实情节合理，也不能证明没有声明的作者规则。悬疑案例中，工具能证明照片/许可依赖链下某些节点不可达；“照片与许可循环依赖”是样例作者对模型的解释，V1 不承诺自动提炼该自然语言根因。

可控性能案例的实际机器、命令、状态数和耗时记录见 [演示记录](demo.md)，只代表对应输入和当前环境的一次测量，不作为性能承诺。
